# دليل Fluent 2 وتطبيقه في Grido Studio

## مصدر الإرشادات وأولوية التعارض

[Microsoft Fluent 2](https://fluent2.microsoft.design/) مرجع خارجي للمبادئ ومكونات التصميم، و[Radix Primitives](https://www.radix-ui.com/primitives) لسلوك الوصول والتركيب. لم تُنفّذ مراجعة شبكية لهذه المراجع في موجة 0 بتاريخ 2026-11-13؛ الأرقام والاختيارات التنفيذية هنا **سياسة Grido المحلية** ما لم يُذكر مصدر محدد متحقق منه. لا تُنسب كثافة المحرر أو نصف قطره أو عتبة 3 ثوانٍ إلى Microsoft/WCAG كمتطلبات عامة.

السلامة وصدق الحالة والوضوح وإمكانية الوصول تسبق المينيمالية والكثافة والحركة. القاعدة النطاقية `.agents/rules/ui-ux-fluent.md` تضبط السياسة؛ `frontend/src/index.css` والمكونات المشتركة تضبط التوكنز الفعلية. لا يُخفّف حارس أو دليل كود في `scripts/docs-gate.mjs` لإخفاء تعارض. هذه الموجة لا تعدّل التوثيق الرسمي أو `.agents/AGENTS.md` ولا تدّعي تحقق GUI.

## 1. المبادئ التصميمية الأساسية

1. **التكيف والتماسك:** تجربة تحترم قدرات المنصة (Windows / Desktop / React).
2. **الهدف والوظيفة:** الحركة والفراغ والظل لخدمة وظيفة، لا بهرجة.
3. **الراحة والإيقاع:** تدرج معلومات ومساحات مدروسة، دون فرض كثافة واحدة على كل سياق.
4. **الوصول الشامل:** تباين مناسب للنص والحالة، أسماء واضحة وتحكم كامل بلوحة المفاتيح، وتركيز مرئي و`prefers-reduced-motion`.

## 2. تنظيم التصميم ومطابقته بالكود

التقسيم التالي خريطة تنظيم محلية، لا حد لعمق شجرة React:

| المستوى             | النطاق                | تطبيق Grido                       |
| ------------------- | --------------------- | --------------------------------- |
| Design Language     | لغة التصميم والتوكنز  | CSS/ثيمات Light وDark             |
| Core UI Kits        | المكونات المشتركة     | Button / Input / Dialog / Toolbar |
| Copilot & AI Kits   | تجارب المعالجة الذكية | Scanner ومؤشرات الترميم           |
| Labs & Experimental | أدوات تجريبية         | الكانفاس ومولد القوالب            |

**Design-to-Code Handshake:** يُقلّل التعشيش الزخرفي ولا تُعشّش بطاقة داخل بطاقة في المفتش، لكن لا قاعدة مطلقة «مستويان فقط» لشجرة React؛ طبقات Radix والسياق والدلالات مطلوبة عند الحاجة. تُطابق الخصائص API المكوّن الفعلي: أغلفة Grido قد تستخدم `variant` و`size` بدلاً من `appearance`/`shape` في Fluent React؛ لا تُمرّر خصائص من مكتبة أخرى افتراضياً.

## 3. التخطيط والمسافات

سلم محلي مستلهم من Fluent، أساسه 4px ويتضمن خطوات وسيطة؛ ليس كل فراغ مضاعف 4px:

| التوكن المرجعي | القيمة | الاستخدام           |
| -------------- | ------ | ------------------- |
| sizeNone       | 0px    | إزالة فراغ          |
| size20         | 2px    | تفاصيل صغيرة        |
| size40         | 4px    | عناصر شديدة الترابط |
| size60         | 6px    | حشو مضغوط           |
| size80         | 8px    | فراغ أيقونة ونص     |
| size100        | 10px   | حشو حقول            |
| size120        | 12px   | تباعد داخلي         |
| size160        | 16px   | حشو حاويات          |
| size200        | 20px   | كتل محتوى           |
| size240        | 24px   | ألواح               |
| size280        | 28px   | أقسام فرعية         |
| size320        | 32px   | شبكة                |
| size360        | 36px   | عناوين              |
| size400        | 40px   | فصل مجموعات         |
| size480        | 48px   | أسطح متوسطة         |
| size560        | 56px   | إيقاع رأسي          |

الأسماء مرجعية؛ الأصناف الفعلية تأتي من الثيم لا من افتراض تسجيل كل اسم. تقنيات الاستجابة: Reposition / Resize / Reflow / Show-Hide / Re-architect. شبكة 12 عمود خيار تخطيط لا فرض على المفتش أو الحوار.

### هرمية المفتش — سياسة Grido

1. رأس مضغوط ذو عنوان وسياق غير مكرر؛ الإظهار والقفل خارج منطقة التعطيل.
2. تبويبات قصيرة واضحة بأسماء وصولية؛ أيقونة وظيفية فقط. يمكن أهلية تبويب حسب نوع العنصر أو القفل أو التحديد (`context eligibility`)، مع اختيار بديل صالح وسبب مفهوم عند الحاجة. لا إلزام بتمكين الأربعة دائماً ولا أدوات وهمية.
3. `FluentSection` صف مسطّح بفاصل، بلا بطاقة متداخلة ولا خاصية `icon`. `FluentSliderField` و`FluentSettingRow` بلا أيقونة مكررة للتسمية.
4. اللون للحالة والمعنى، لا شارة زخرفية مفروضة في رأس كل قسم.
5. 10px (`space-y-2.5`) بين الأقسام و12px حشو داخلي عند الحاجة، دون أغلفة وظلال متكررة.

## 4. المواد والأسطح

- **Solid:** الأسطح الأساسية عبر `bg-background`/`bg-card`/`bg-muted` من الثيم، لا hex خام في JSX.
- **Acrylic-inspired:** مادة ويب شبه شفافة للأسطح العائمة فقط، مثلاً `bg-popover/95 backdrop-blur-xl border-border/60`، مع بديل معتم إن أثّر blur في الوضوح أو الأداء. ليست مادة Windows الأصلية بمجرد CSS.
- **Mica:** مادة نافذة أصلية عند دعمها من الرنتايم؛ CSS وحده لا يثبت تطبيقها.
- **Smoke:** خلفية حوار تعزل السياق بصرياً؛ لا يُفرض blur على كل سطح.

## 5. الارتفاع والظلال

مفهوم Key/Ambient Shadow مرجع تصميم خارجي، أما قيم Grido في `frontend/src/index.css` و`shadow-fluent-*` فسياسة محلية. تُستخدم الأصناف الموجودة فقط؛ `shadow-fluent-16` للأسطح العائمة، لا `shadow-fluent-28` أو توكن غير معرّف. حدّ خفيف `border-border/60` يحافظ على فصل السطح في الثيمين، ولا يُختزل الوصول في ظل أو Specular Stroke.

## 6. الأشكال والمقاسات والتركيز

الأشكال الأساسية: المستطيل للتحكم، الدائرة للأفاتار/الأزرار الدائرية، الكبسولة للوسوم والمفاتيح، ومؤشر tooltip عند الحاجة.

### استدارة سطح المكتب — سياسة Grido المعتمدة 21 أكتوبر 2026

الأساس `--radius: 0.375rem` (6px): `rounded-md` = 4px، `rounded-lg` = 6px، `rounded-xl` = 10px.

| السطح                            | الصنف                         |
| -------------------------------- | ----------------------------- |
| Control / Inset                  | `rounded-md` بلا ظل داخلي     |
| Floating overlay                 | `rounded-lg shadow-fluent-16` |
| Modal                            | `rounded-xl shadow-fluent-16` |
| Inspector panel                  | `rounded-none`، صفوف وفواصل   |
| Pill / Avatar / Circular control | `rounded-full`                |

لا `rounded-2xl`/`rounded-3xl` في كود أو أمثلة المحرر؛ أي استثناء خارج القاعدة يحتاج مبرر نطاق وموافقة صريحة، دون توسيع الحراس القائمة هنا. رأس اللوح `min-h-12` (حد أدنى 48px مع التفاف العنوان دون بتر)، و`FluentSection` مسطّح بلا ظل. التبويب الأفقي بخط سفلي نشط، لا كبسولة عائمة.

### ارتفاع السطح ليس حد النقر

| الارتفاع      | الاستخدام المحلي           |
| ------------- | -------------------------- |
| `h-7` (28px)  | تحكم compact بمؤشر دقيق    |
| `h-8` (32px)  | Input/Select وأزرار قياسية |
| `h-9` (36px)  | إجراءات بارزة              |
| `h-10` (40px) | إجراءات رئيسية كبيرة       |
| `h-12` (48px) | أشرطة أوامر                |

- **compact:** حد التفاعل الفعلي الأدنى 28×28px في سطح المكتب ذي المؤشر الدقيق.
- **coarse:** حد التفاعل الفعلي الأدنى 44×44px للمس/المؤشر الخشن. `TOUCH_TARGET_MIN` يحافظ على قيمة 44 للتوافق، و`COMPACT_TARGET_MIN` يصف سياق 28 منفصلاً.
- تُقاس المساحة التي تستقبل المؤشر بعد التحويل والقص والتداخل؛ لا حجم glyph ولا مساحة فارغة غير قابلة للنقر. أيقونة 16px داخل زر 44px ممكنة. المقاسات سياسة منتج لا ادعاءً بحد WCAG واحد.
- العقود القديمة الأصغر، ومنها `h-6 w-6` للشريط السريع، تحتاج مراجعة حدود التفاعل ولا تُحذف أدلتها صامتاً. اختبار توكن أو مصدر ليس تحققاً لحدود DOM الفعلية.

### توكنز الصقل — 5 نوفمبر 2026

- `text-control` = 12px / 18px للتسميات والحقول؛ تبقى `xs/mini/micro` للسياقات المتخصصة، بلا تكبير شامل. مسجّل في `frontend/src/lib/utils.ts` لـ tailwind-merge.
- `bg-primary-action` و`hover:bg-primary-action-hover` للأزرار التعبوية مع `text-primary-foreground`؛ `text-primary` و`border-primary` للتمييز، لا `bg-primary` الخام مع نص أبيض.
- `border-control-border` للحقول، و`border-border` للفواصل.
- `bg-preview-surface` لمعاينات المكتبات، لا للمستند أو SVG المصدر.

الحد الافتراضي 1px؛ حلقة التركيز:

```css
focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2 focus-visible:ring-offset-background focus-visible:outline-none
```

تُحفظ الحلقة مرئية غير مقصوصة، ولا تُلغى للوصولية باسم المظهر.

## 7. الحركة والأداء

الأزمنة المحلية في `MOTION`: 50/100/150/250/400/600ms، والمنحنيات spring/decelerate/accelerate في الكود مرجع للاتساق، لا إلزام بحركة لكل عنصر. حركة اللوحات التفاعلية أسرع من مشاهد التقديم؛ يُحترم `prefers-reduced-motion`.

للألواح الجانبية والأكورديون والأدراج: إظهار مباشر وتلاشي قصير عبر `motion-safe:animate-in motion-safe:fade-in motion-safe:duration-100`، وانتقالات لون/سهم حتى 150ms مع `motion-reduce:transition-none`. يُتجنب تحريك الارتفاع المستمر والزنبرك البطيء في هذا السياق. تحريك height قد يستدعي layout/paint؛ لا ادعاء بإجهاد GPU ثابت أو بأن CSS يضمن GPU أو أداء أفضل. أي تغيير أداء يحتاج قياساً، لا تعميم منع كل JavaScript/Framer Motion. وضع تقليل الحركة لا يخفي الحالة أو يمنع العمل.

## 8. الانتظار الصادق — سياسة Grido المحلية

التقدير الزمني يختار نمط تغذية راجعة، ولا ينتج نسبة إنجاز.

| التقدير/السياق           | النمط                   | شرط الصدق                                        |
| ------------------------ | ----------------------- | ------------------------------------------------ |
| أقل من 1s                | none                    | منع التكرار مع تجنب وميض مؤشر                    |
| 1s إلى 3s، شامل الحدين   | spinner                 | حالة انتظار غير محددة                            |
| أكثر من 3s أو مدة مجهولة | indeterminate افتراضياً | spinner أو شريط بلا نسبة، لا تقدم وهمي           |
| أكثر من 3s مع measured   | progress محدد           | تقدم مقاس من العملية؛ المدة وحدها ليست قياساً    |
| عمل خلفي                 | toast                   | إبقاء العمل ممكناً وحالة حقيقية، بلا نسبة مخترعة |
| تحميل هيكل معروف         | skeleton                | تقليل الحركة واحترام أبعاد المحتوى               |

`pickWaitComponent(expectedMs, progressCapability?)` يحافظ على الاستدعاء ذي المعامل الواحد واتحاد الإرجاع القديم. القدرة الاختيارية `'indeterminate' | 'measured'` افتراضها `'indeterminate'`؛ الانتظار الطويل يعيد `'spinner'` افتراضياً، و`'progress'` فقط مع `'measured'`. القيم الزمنية غير الصالحة/غير المحدودة تُعامل كمدة مجهولة وتعيد spinner. `'toast'` و`'skeleton'` باقيتان في نوع الإرجاع للتوافق، ولا تختارهما الدالة من مدة وحدها. لا زيادة تلقائية بالنسبة بواسطة مؤقت ولا إكمال حتى استجابة مؤكدة؛ ETA لا يُعرض إلا بتقدير مستند إلى قياس صالح.

### قاموس الانتظار

- الحفظ والتصدير: `جاري الحفظ ...`، `جاري التصدير بجودة عالية ...`، `جاري إعداد الملف ...`.
- التطبيق والإنشاء: `جاري التطبيق ...`، `جاري إنشاء المشروع ...`، `جاري تجهيز القالب ...`.
- المعالجة: `جاري العزل ...`، `جاري المعالجة وتحسين الوضوح ...`، `جاري مسح المستند ...`، `جاري ضبط الوجه ...`.
- التحديث والمزامنة: `جاري تحميل التحديث ...`، `جاري التثبيت وإعادة التشغيل ...`، `جاري المزامنة ...`.

مسافة قبل النقاط، والنص يصف المرحلة الفعلية. بعد إغلاق الحوار يبقى العمل غير المنتهي ذا ملكية غير صفرية عند المالك الصحيح؛ إما إلغاء حقيقي أو نقل ملكية خلفية وسحب صلاحية الجلسة القديمة. النتائج و`catch`/`finally` محروسة بمعرّف محاولة/جيل، فلا تطبق أو تغلق جلسة أحدث أو تصفّر عملها. إعادة الفتح لا ترث تحميل الحوار القديم. `useEffect` على الفتح مع `finally` غير محروسين لا يثبتان السلامة.

## 9. الذكاء الاصطناعي المسؤول

1. توضيح استخدام AI وإتاحة التحقق من المخرجات.
2. لا أنسنة أو ادعاء آراء/عواطف؛ وصف حقائق ونتائج.
3. توقعات واقعية وتعليمات/تنبيهات غير مكررة، لا تُحذف باسم الاختصار.
4. إلغاء حقيقي عند دعمه، Undo وتحكم بالمخرجات؛ إن تعذر الإلغاء يُذكر القيد ولا يُقدّم زر كاذب.
5. رسائل مرحلة دقيقة، لا تقدم اصطناعي أو نجاح قبل الاستجابة.

## 10. المكونات والقدرات

المراجع تشمل Button/Input/Combobox/Select/Checkbox/RadioGroup/Switch/Slider/SpinButton/TagPicker، وDialog/Drawer/Accordion/Tabs/Toolbar/Nav/Tree/Divider، وBadge/Avatar/Progress/Spinner/Skeleton/Toast/Tooltip/Popover. هذا قاموس لا ضمان بأن كل مكوّن Fluent React أو `FluentProvider` مركّب في Grido؛ تُستخدم أغلفة المشروع وAPI المثبتة.

### منتقي الألوان المحلي

`ColorWheel` عجلة HSV على Canvas وشريط سطوع؛ لا استبدال بمكتبة خارجية أو مربع تشبع في المفتش. HEX و«شفاف» و«قطارة الشاشة» أدوات وظيفية؛ يُحذف التكرار لا تعليمات الاستخدام اللازمة. الوصولية: `role="slider"` و`aria-valuetext` للدرجة والتشبع، شريط السطوع بقيمة 0–100، وأسهم/Shift للتحكم.

## 11. أمثلة محلية ملتزمة بالتوكنز

### نافذة المحرر: أغلفة Grido تدير Portal والتركيز والاتجاه

```tsx
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
  DialogCloseButton,
} from '@/components/ui/dialog';

<Dialog open={open} onOpenChange={onOpenChange}>
  <DialogContent showCloseButton={false} aria-describedby={undefined}>
    <DialogHeader>
      <div className="flex items-center justify-between gap-3">
        <DialogTitle>معاينة</DialogTitle>
        <DialogCloseButton />
      </div>
    </DialogHeader>
    <div className="p-4">{/* محتوى يعرّف نفسه، بلا تعليمات محذوفة */}</div>
  </DialogContent>
</Dialog>;
```

`aria-describedby={undefined}` هنا فقط لأن المثال بلا وصف ضروري؛ في إجراء ذي مخاطر/قيود يبقى وصف مرتبط واضح. لا تكرار `createPortal` حول الغلاف؛ Portal Radix الأصلي يمكن توجيهه إلى حاوية مناسبة خارج التحويل/القص مع الحفاظ على نطاق الحوار، ولا يُفرض `document.body` دائماً.

### تحكم مقسم: المكوّن المشترك يدير دلالات الاختيار

```tsx
import { FluentSegmentedControl } from '@/components/ui/blocks/fluent-segmented-control';

<div className="flex items-center gap-2 border-b border-border/40 bg-background p-2">
  {/* API الخيارات والأسماء والتحكم من المكوّن المشترك الفعلي */}
  <FluentSegmentedControl {...segmentedProps} />
</div>;
```
