# قواعد واجهة المستخدم وتجربة الاستخدام (UI/UX & Fluent 2)

## مصدر القواعد وأولوية التعارض

- **الأولوية:** السلامة وصدق الحالة ووضوح الإجراء وإمكانية الوصول تسبق الكثافة البصرية والاختصار والحركة. لا يجوز حذف تسمية أو تعليمات أو تحذير مطلوب باسم المينيمالية.
- **المراجع الخارجية:** [Microsoft Fluent 2](https://fluent2.microsoft.design/) و[Radix Primitives](https://www.radix-ui.com/primitives) مصادر للمبادئ وسلوك المكتبات، وليسا إثباتاً لكل رقم أو سياسة أدناه. لم تُنفّذ مراجعة شبكية للمراجع في موجة 0 بتاريخ 2026-11-13.
- **سياسة Grido المحلية:** كثافة محرر سطح المكتب، سلم الاستدارة، مهلات اختيار مؤشر الانتظار، تنظيم المفتش ومصدر الأوامر قرارات محلية؛ مصدر تفاصيلها المهارات المعنية والكود الفعلي. لا تُنسب هذه القرارات إلى Microsoft أو WCAG أو Radix كمتطلبات عامة.
- **أدلة الامتثال:** الحراس النصيون واختبارات الوحدة لا يثبتون حدود النقر الفعلية أو الوصولية البصرية. يُحافظ على أدلة الكود في `scripts/docs-gate.mjs` والحراس الموجودة؛ لا يُحذف تأكيد أو يُخفّف لإخفاء فشل. هذه الموجة لا تعدّل التوثيق الرسمي أو `.agents/AGENTS.md`.

## واجهة المستخدم وتجربة المستخدم (UI/UX)

- **نظام تصميم Microsoft Fluent 2:** الاسترشاد بالمبادئ والمكونات وبالمهارة المرجعية (`.agents/skills/fluent2-design-system/SKILL.md`). تُختار شبكة التخطيط والمواد بحسب السياق؛ شبكة 12 عمود والأكريليك ليسا إلزاميين لكل شاشة. يُستعمل سلم المسافات المعتمد، بما فيه 2/6/10px، لا مضاعفات 4px حصراً.
- **هرمية الاستدارة المعمارية — سياسة Grido لسطح المكتب (معتمدة 21 أكتوبر 2026):**
  - الأساس هو `--radius: 0.375rem` (6px) في `frontend/src/index.css`، فالقيم الفعلية `rounded-sm` = 2px · `rounded-md` = 4px · `rounded-lg` = 6px · `rounded-xl` = 10px.
  - عناصر التحكم الدقيقة (Controls & Inputs): الأزرار، حقول الإدخال، القوائم المنسدلة، المفاتيح، وعناصر القوائم الداخلية — `rounded-md` (4px).
  - الأسطح الداخلية (Inset Surfaces): البطاقات داخل لوحة أو حوار — `rounded-md` (4px) بلا ظل وبلا حدّ ثقيل.
  - الأسطح العائمة (Floating Overlays): `Popover` و`DropdownMenu` و`SelectContent` و`CommandPalette` وقوائم السياق والأشرطة العائمة — `rounded-lg` (6px) مع ظل `shadow-fluent-16`.
  - النوافذ والحوارات (Modals & Dialogs): `rounded-xl` (10px) مع `shadow-fluent-16`. لا `rounded-2xl`/`rounded-3xl` في أمثلة المحرر أو كوده؛ أي استثناء يحتاج مبرر نطاق وموافقة صريحة، ولا يُوسّع حارس الكود ضمن هذه الموجة.
  - ألواح الخصائص (Panels/Inspector): سطح مسطّح واحد بلا نصف قطر — صفوف متتابعة يفصلها خط شعري `border-b border-border/55`؛ البطاقة لا تُستخدم لتغليف كل سطر إعدادات.
  - الكبسولات والأفاتار والأزرار الدائرية: `rounded-full`.
- **سلم الارتفاعات وحدود التفاعل — سياسة Grido المحلية:**
  - عناصر التحكم القياسية (32px): `h-8` لحقول الإدخال (`Input`)، القوائم (`Select`)، والأزرار الثانوية والتنفيذية.
  - عناصر التحكم المدمجة: حد النقر الفعلي الأدنى 28×28px (`h-7 w-7`) في سياق سطح المكتب ذي المؤشر الدقيق (`compact`).
  - اللمس والمؤشر الخشن (`coarse`): حد التفاعل الفعلي الأدنى 44×44px؛ لا يكفي تكبير الأيقونة أو وجود فراغ حول زر أصغر. تُقاس المساحة التي تستقبل المؤشر بعد التحويل والقص والتداخل، ويمكن إبقاء الأيقونة أصغر داخلها. هذه مقاسات سياسة المنتج وليست ادعاءً بحد WCAG موحّد.
  - العقود القائمة الأصغر، مثل الشريط السريع ذي `h-6 w-6`، لا تُلغى صامتاً: تُسجّل كفجوة/استثناء يحتاج مراجعة حدود النقر، وتبقى أدلة الاختبارات القائمة دون تخفيف.
  - أزرار الإجراءات البارزة (36px): `h-9` لأزرار الـ Hero Actions؛ أشرطة الأوامر الرئيسية (48px): `h-12`. ارتفاع السطح ليس وحده إثباتاً لحدود هدف التفاعل.
- **حلقة التركيز المزدوجة (Dual Focus Ring Standard):** للعناصر التفاعلية القابلة للتركيز بواسطة لوحة المفاتيح: `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2 focus-visible:ring-offset-background focus-visible:outline-none`. لا تُقصّ الحلقة ولا يُلغى التركيز بلا بديل مرئي.
- **ثوابت تجربة الانتظار (Wait UX Invariants):** النص يصف العمل الفعلي: `جاري الحفظ ...` أو `جاري التصدير ...`، مع مسافة قبل النقاط. التقدير الزمني لا يثبت نسبة إنجاز: أقل من ثانية بلا مؤشر مزعج مع منع النقر المكرر؛ من 1 إلى 3 ثوانٍ spinner؛ بعد 3 ثوانٍ أو عند مدة مجهولة مؤشر غير محدد (`indeterminate`) افتراضياً. لا يُستخدم شريط محدد إلا مع تقدم مقاس (`measured`) من مصدر العملية، ولا نسبة/وقت متبقٍ وهمي أو مبني على مؤقت. الخلفية يمكن أن تستخدم toast صادقاً، والـ skeleton لتحميل هيكل معروف فقط. تفاصيل القدرة الاختيارية في `pickWaitComponent` بالمهارة والكود.
- **الاعتماد الوظيفي على الأيقونات (Icon-Driven UI — حاجة بصرية لا فرض ولا زينة):** الأيقونة تختصر معنى وظيفياً مستقلاً (إجراء، حالة، تصنيف) ولا تكرر التسمية في المفتش الضيق. أيقونات الأفعال مفيدة حين تحمل معنى لا يوصله النص؛ `FluentSection` وصفوف `FluentSliderField` و`FluentSettingRow` بلا خاصية `icon`. الزر الأيقوني يحتاج اسماً وصولياً على العنصر التفاعلي؛ الأيقونة الزخرفية تُخفى عن قارئ الشاشة. الـ Tooltip لا يعوّض الاسم أو تعليمات مطلوبة.
- **حظر الحشو البصري (Zero Visual Filler Standard):**
  1. **لا أيقونة زخرفية:** لا تُضاف أيقونة للجمالية أو الاتساق فقط. عنوان القسم/البطاقة بلا أيقونة في `FluentSection`؛ الأيقونات للأفعال والحالات ذات المعنى المستقل.
  2. **العنوان الفرعي ليس افتراضاً:** الوصف غير المكرر مفيد حين يوضح نتيجة أو قيداً أو خطراً أو خطوة لازمة. لا تُنقل هذه المعلومات الضرورية إلى Tooltip وحده.
  3. **حتى العنوان قد يكون زائداً:** يُحذف عنوان بطاقة مكرر إذا ظل السياق والاسم الوصولي واضحين. `DialogTitle` إلزامي ولو `sr-only`. يبقى وصف Dialog/AlertDialog الضروري لفهم الإجراء وعواقبه؛ عند عدم الحاجة الفعلية لوصف Dialog يُضبط `aria-describedby={undefined}` صراحة، لا ارتباط إلى معرّف مفقود.
  4. **اختبار الحذف قبل التسليم:** يُحذف العنصر فقط بعد التحقق أن المستخدم لا يفقد معلومة أو وظيفة أو اسماً وصولياً. عند الشك في السلامة أو الفهم تُحفظ التسمية/التعليمات حتى تتضح الحاجة.
  5. **حارس تقليل النصوص (Text Minimalism Gate — ملزم في كل تعديل قادم):** يُمنع تكرار اسم القسم أو قيمة مرئية أو شرح فعل واضح. تُحفظ تسميات الحقول والوحدات اللازمة والأسماء الوصولية ورسائل الخطأ/التحقق والتعليمات والتحذيرات والنتائج المهمة. يُذكر في المراجعة ما يفقده المستخدم لو حُذف النص؛ الاختصار لا يتقدم على السلامة والوضوح والوصولية.
- **مظهر نظيف ومحترف (Clean & Professional Look):** تخطيط مضغوط ونظيف على غرار أدوات التصميم العالمية، دون فرض حد مطلق لعمق شجرة React؛ يُقلّل التعشيش الزخرفي ولا تُحذف طبقات السياق أو الوصولية اللازمة.
- **فصل القوائم العائمة بـ Portal:** تُفصل القوائم المتأثرة بـ containing block أو القص الناتج عن `transform` عن الحاوية المسببة. يُفضّل Portal الأصلي في Radix أو الغلاف المشترك، بلا Portal مزدوج. يمكن `React.createPortal` للمكونات المخصصة؛ الحاوية المناسبة خارج التحويل/القص وتحافظ على نطاق الحوار وإدارة التركيز والاتجاه والثيم. لا يُفرض `document.body` لكل حالة، ولا يُعالج الخطأ برفع `z-index` وحده.
- **تثبيت المساطر بحواف الواجهة (Viewport-Fixed Rulers):** لا تُلصق المساطر بحاوية الورقة؛ تُثبت في حواف الشاشة خارج منطقة التمرير، بحيث تتحرك الورقة وتتكبر أسفلها.
- **الالتقاط الديناميكي لتخطيط الكولاج (Dynamic Collage Resolution):** يُمنع فرض قوالب كولاج افتراضية مشفرة عند التنشيط أو التبديل. تُقرأ أبعاد وتخطيط `collageTemplate` الذي حدده المستخدم وتُزامن المدخلات مع الـ Store فوراً.
- **ملكية عمليات الحوار بعد الإغلاق (Modal Async Ownership Invariant):** إعادة الفتح لا تعرض حالة تحميل قديمة، لكن عدد/حالة العمل غير المنتهي لا تُصفّر كذباً إن استمر بالخلفية؛ تبقى له ملكية غير صفرية لدى المالك الصحيح حتى الاكتمال. الإغلاق إما يلغي العمل فعلياً إن أمكن، أو يسحب صلاحية المحاولة لتحديث الحوار مع نقل الملكية لمالك خلفي. كل محاولة مرتبطة بمعرّف محاولة/جيل جلسة؛ النتائج و`catch` و`finally` القديمة لا تطبق بيانات ولا تغلق جلسة جديدة ولا تصفّر تحميل محاولتها. `useEffect` على `open` و`try ... finally` المجردان ليسا ضماناً للسلامة؛ التنظيف والإكمال كلاهما محروسان بالملكية.
- **التصميم القياسي للمساطر ونقطة البداية (Standard Ruler Aesthetics & Origin Highlighting):** أبعاد 20px وتدرج Major/Mid/Minor عبر SVG مجمع؛ تُميّز `(0,0)` وأطراف الورقة باللون الرئيسي لإدراك موضعها.
- **معايير نوافذ التحديث والملاحظات المنسقة (Update Dialog UX Standard):** مقارنة بصرية تراعي RTL بين المثبت والأحدث، وتنسيق ملاحظات Markdown كقوائم وعناوين واضحة؛ أيقونات وظيفية فقط دون زخرفة مفروضة.
- **معيار الاختصار والتركيز النصي (Concise Professional UI Terminology Standard):** تُفضّل كلمة أو كلمتان (`فتح`, `تصدير`, `تكرار`, `حذف`) حين يبقى الإجراء واضحاً؛ يمكن زيادة النص لتمييز إجراء أو عاقبة مهمة. Tooltip للتفاصيل الثانوية، لا بديلاً للتسمية/التحذير المطلوب. جدول الصياغات في مهارة `grido-ui-designer-guide`.
- **تموضع زر الإغلاق في شريط عنوان النوافذ (Dialog Title Bar Close Button Invariant):** `DialogCloseButton` داخل `DialogHeader` عبر `flex items-center justify-between`، و`showCloseButton={false}` على `DialogContent` لمنع زر عائم أو مكرر؛ لا حذف للاسم الوصولي.
- **دمج وتكثيف التصنيفات في الواجهات والمكتبات (Consolidated Categorization Standard):** دمج الفئات المتشابهة دلالياً، مع إبقاء الفروق اللازمة للتصفح، لا فرض عدد مطلق يحذف تصنيفاً وظيفياً.
- **هرمية الألوان وأهلية التبويبات (Color Hierarchy & Context Eligibility):** تنظيم ثابت حيث تكون الأدوات ذات معنى، لا إلزام بإتاحة كل تبويب لكل نوع عنصر. يمكن إخفاء/تعطيل تبويب لا قدرة له بحسب السياق أو القفل أو التحديد، مع سبب واضح عند الحاجة وبديل نشط صالح ومزامنة الاختيار؛ لا يُعطّل تبويب قادر فعلاً ولا يُعرض محتوى وهمي. يُمنع تفريع تبويبات داخلية مكررة:
  1. **التنسيق (Style):** البنية الهندسية والطباعية (الخط، القياسات، المحاذاة، الأنماط، الاستدارة).
  2. **الألوان/الضبط (Colors/Adjust):** اللون والتعبئة أو ضبط الصور بحسب القدرة الفعلية؛ لا أدوات صور وهمية للنصوص/الأشكال.
  3. **التأثيرات (Effects):** الظلال، التوهج والنص المنحني عند دعمه.
  4. **الترتيب (Arrange):** الموضع والمحاذاة والتدوير والقلب.
- **حارس المزامنة التلقائية لألواح العمل عند تحديد العناصر (Workspace Drawer Selection Sync Invariant):** عند تعديل الحالة الافتراضية للأدراج يجب ضمان المزامنة مع الكانفاس: التحديد ينشط `properties` ويفتح الدرج على الشاشات العادية؛ إلغاء التحديد يعيد الحالة السابقة. تُغطّى نقاط التوقف والتبديل باختبارات `frontend/test/use-workspace-panels.test.ts`.
- **مصدر واحد للاختصارات ولوحة الأدوات (Single Shortcut & Palette Invariant):** الاختصارات العامة تُسجّل حصراً في `frontend/src/hooks/use-keyboard-shortcuts.ts`، وأوامر لوحة الأدوات تُعرَّف حصراً في `WORKSPACE_COMMANDS` و`WORKSPACE_STATE_COMMANDS` ضمن `frontend/src/lib/workspace-tools.ts`، واللوحة الوحيدة هي `WorkspacePanelRail` (Ctrl+K). يُمنع إجبارياً إنشاء لوحة أوامر ثانية أو مستمع `keydown` خام على `window` لأي اختصار (يختطف الاختصار ويتجاوز حراس الحقول النصية)، ويُمنع ربط أمر بحدث `grido:*` بلا مستمع حقيقي في الموضع المالك للقدرة، ويُمنع إعلان اختصار في الواجهة بلا تسجيل مقابل بنفس الصيغة. التفاصيل في `.agents/skills/grido-ui-designer-guide/SKILL.md` القسم 6.
- **حظر console.error المباشر في العمليات الحساسة (Unified Logger Invariant — RV-4):** لا `console.error`/`console.warn` خام في التصدير والطباعة والملفات والحوارات والعمليات الحساسة؛ يُستخدم `createLogger('ComponentName')` من `src/lib/logger` لسجل التشخيص.
- **حركة سطح المكتب وأداؤها (Snappy Desktop Motion):** سياسة محلية للألواح والأكورديون والأدراج: إظهار مباشر مع تلاشي CSS قصير (`motion-safe:animate-in motion-safe:fade-in motion-safe:duration-100`)، وانتقالات الألوان/الأسهم حتى 150ms مع `motion-reduce:transition-none`. يُتجنب تحريك الارتفاع المستمر والزنبرك البطيء في هذه الأسطح؛ لا تُعمم القاعدة على كل React أو مكتبة حركة. تحريك الارتفاع قد يسبب layout/paint، لكن CSS ليس ضمان GPU أو أداء أفضل؛ أي ادعاء أداء يحتاج قياساً، ولا تُخترع أرقام أو أسباب GPU. تقليل الحركة لا يخفي حالة انتظار أو معلومة.
- **واجهات الأجهزة المتنقلة الخدمية (Mobile Utility):** الاسترشاد بـ Apple HIG مع وسم قرارات المنتج محلياً: صفحة `/cam` أداة بلا حشو تسويقي، تطلب الكاميرا الخلفية عبر `facingMode: { ideal: "environment" }` ودقة ملائمة للقدرة، وتعرض حالة الربط ومعرف الجلسة بوضوح. الاهتزاز اختياري حسب دعم `navigator.vibrate` والتفضيلات؛ لا يُدّعى نجاح إرسال قبل استجابة مؤكدة.

## التفضيلات وتخزين الواجهة (Frontend Preferences)

- **استخدام LocalStorage لتفضيلات الواجهة الخفيفة:** للتفضيلات التي لا تؤثر على بنية المشروع (مثل Pinned Projects وطرق العرض) يُفضّل `localStorage` (مثل `grido_pinned_projects`) بدل تعديل مخطط Go/قاعدة البيانات دون حاجة.
