# تقرير 11 — تجاوز تخويل حرج في دوال الأدمن (`is_admin()` تعيد NULL) — 2026-09-26

> **الخطورة:** 🔴 حرجة (CVSS تقديري 9.1) — تجاوز تحكم وصول كامل بواجهة عامة.
> **الحالة:** ✅ أُصلحت على الإنتاج واختُبرت — هجرة `20260926160117_fix_is_admin_null_authz_bypass.sql`.
> **المصدر:** تدقيق أمني إضافي على الإنتاج عبر Supabase MCP (استجابةً لطلب البحث عن مزيد من الخروقات).

---

## 1. الملخّص

`public.is_admin()` كانت مُعرَّفة كالتالي:

```sql
RETURN (
  (auth.jwt() -> 'app_metadata' ->> 'role') = 'admin'
  OR EXISTS (SELECT 1 FROM public.admin_users WHERE user_id = (select auth.uid()))
);
```

عندما لا يوجد مفتاح `role` داخل `app_metadata` (وهو الحال الطبيعي لكل مستخدم عادي، إذ يكون `app_metadata = {}`)، فإن `({} ->> 'role') = 'admin'` تساوي **NULL**، و`EXISTS(...)` لغير المسؤول تساوي `FALSE`. وبحسب منطق SQL ثلاثي القيم فإن:

```
NULL OR FALSE = NULL
```

فكانت `is_admin()` تعيد **`NULL` لا `FALSE`**. وبما أن دوال الأدمن تفحص بـ`IF NOT public.is_admin() THEN RAISE …`، فإن `NOT NULL = NULL`، و`IF NULL` تُعامل كـ«خطأ» ⇒ **لا يُرفع الاستثناء** ⇒ تمرّ العملية بلا أي تحقق.

**هذا تجاوز كامل للتحقق، ودُوَل الأدمن ممنوحة `EXECUTE` لأدوار `anon` و`authenticated`.**

## 3. الإصلاح (هجرة `20260926160117`)

1. **الجذر:** `is_admin()` تعيد `boolean` دائماً:
   ```sql
   RETURN COALESCE((auth.jwt() -> 'app_metadata' ->> 'role') = 'admin', false)
     OR EXISTS (SELECT 1 FROM public.admin_users WHERE user_id = (select auth.uid()));
   ```
2. **دفاع في العمق:** كل فحص صار `IF public.is_admin() IS NOT TRUE THEN RAISE` (بدل `IF NOT …`)، وكذلك فحص `check_and_record_ai_usage` صار `… AND public.is_admin() IS NOT TRUE`. هذا يمنع تكرار الصنف نفسه لو أُعيد كسر `is_admin` مستقبلاً.
3. `NOTIFY pgrst, 'reload schema';`

**التحقق بعد الإصلاح:** الجدول أعلاه (الصفوف 2–4 صارت مرفوضة، والصف 5 لا يزال يعمل)، و`is_admin()` صارت `false` غير فارغة للمستخدم العادي. كما أُعيد تشغيل سلسلة `auth_rls_initplan` وبقيت `0`.

## 4. الدروس وبوابات المنع المقترحة

- **قاعدة عامة:** لا تكتب `IF NOT some_boolean_function() THEN RAISE` في دوال `SECURITY DEFINER`؛ استخدم `IS NOT TRUE`. دالة تعيد `NULL` لا تُغلق المسار.
- **اختبار انحدار آلي (مقترح):** بوابة CI تشغّل هذا السيناريو عبر MCP/قاعدة اختبار: تحاول استدعاء كل `admin_*` بدور `anon` وتتوقّع الفشل. لا يمكن تشغيلها في CI الحالي بلا قاعدة، لكنها ممكنة كوظيفة ليلية.
- **بوابة أمنية مقترحة:** سكربت يفحص تعريفات الدوال الحيّة ويفشل إذا وُجد `IF NOT <fn>()` بدل `IS NOT TRUE`.
- **تقييد المنح (مقترح، لم يُنفَّذ):** سحب `EXECUTE` على `admin_*` من دور `anon` يضيف طبقة ثانية — يتعارض جزئياً مع قاعدة منح الـanon في `AGENTS.md:82` ويحتاج قرار المالك. الفحص الداخلي المُصلَّح يكفي اليوم.

## 5. العلاقة بالتقرير 09

التقرير 09 (تطبيق الإدارة) رصد سلسلة تصعيد أخرى عبر `plan='enterprise'` وأُغلقها. لكنه حكم بأن دوال `admin_*` «محميّة داخلياً بفحص `is_admin`» — وهذا صحيح منطقياً لكنه **أخفق في اختبار الحالة الحدّية `NULL`**؛ فالتحقق الداخلي كان موجوداً في الكود لكنه غير فعّال عند قيمة `NULL`. الدرس: «وجود الفحص» ≠ «فعالية الفحص» — يجب اختبار الفحص ضد قيم غير متوقعة (NULL تحديداً).
