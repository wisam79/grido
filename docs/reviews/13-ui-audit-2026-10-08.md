# Grido Studio — Full UI Audit: Verified Defect Register

> **Scope:** `frontend/` (React 19 + TypeScript + Tailwind v4 + Radix + Zustand v5 + Konva, Wails v3 shell).
> **Method:** line-level read of every UI layer (shell, toolbar, panels, properties, dialogs, Konva engine, store slices, hooks, CSS/theme). Every item below was confirmed against the source at the cited line.
> **Baseline is green:** `npx tsc --noEmit` → 0 errors · `npx eslint src --max-warnings 0` → 0 problems. So every item is a *logic/architecture/physics* defect, not a compile failure.

**Totals:** 🔴 7 Critical · 🟠 17 High · 🟡 25 Medium · ⚪ 6 Low

## 1. Critical — a feature is broken, or the user loses work

### C1 · The app renders LTR at the document root
`frontend/index.html:2` — `<html lang="ar" class="dark">`. **No `dir="rtl"`**, and grep confirms **0** occurrences of `documentElement.dir` in `src`.
Consequence: every Radix overlay (`Dialog`, `AlertDialog`, `Select`, `DropdownMenu`, `Popover`, `Tooltip`, `Toast`) portals into `document.body` and inherits **LTR**, while panels opt in individually with local `dir` attributes. C1 is the root cause of C2/C3/C4 and H17 — the primitives look RTL-correct in isolation and are wrong in the real app.
**Fix:** `<html lang="ar" dir="rtl" class="dark">`, then delete the now-redundant per-subtree `dir` re-declarations.

### C2 · Select indicator lands on top of the label
`components/ui/select.tsx:94` — `relative flex w-full … pr-7 pl-2`; `:99` — `absolute right-1.5`. In RTL the ✓ renders exactly where the text begins, and padding reserves space on the wrong edge.
**Fix:** `pe-7 ps-2` + `end-1.5`.

### C3 · DropdownMenu check/radio indicators mirror to the wrong side
`components/ui/dropdown-menu.tsx:67` and `:89` — `pr-2 pl-7` + `absolute left-1.5`. Breaks outright when a consumer passes `dir="rtl"` (already done at `stickers/StickerStudioDialog.tsx:734`). Also `:130` and `:159` use `ml-auto` instead of `ms-auto`.
**Fix:** `ps-2 pe-7` + `end-1.5`; `ms-auto`.

### C4 · Export progress bar fills from the wrong direction
`components/ui/progress.tsx:25` — `style={{ transform: `translateX(-${100 - (value || 0)}%)` }}`. Radix sets no `dir`, so inside any RTL dialog (`dialogs/export-dialog.tsx:415`) the bar grows left-to-right while a user reading right-to-left expects the opposite.
**Fix:** `scaleX(value/100)` with `origin-left rtl:origin-right`.

### C5 · Canvas chrome never follows the theme
`lib/canvas/canvas-colors.ts:11-19` memoizes `getComputedStyle(document.documentElement)` in a module singleton, and the invalidation escape hatch `invalidateCanvasColors()` (`:22`) has **0 callers** repo-wide (grep-verified).
Consequence: guides, transformer anchors, ruler cursor, collage overlays, slot placeholders, scanner beams and dropzones stay at the colors of whichever theme happened to be active at module load — switching to dark permanently renders light-theme canvas chrome.
**Fix:** call `invalidateCanvasColors()` from `use-theme.ts`'s class-sync effect (`:42-54`), and re-read colors in the affected Konva nodes.

### C6 · Corrupt autosave is hard-deleted with no backup and no notice
`hooks/use-autosave.ts:59-66` — on any parse/zod failure: `console.error(...)` then `await ClearAutoSave()` (hard `os.Remove` on the Go side). No quarantine, no user prompt, no toast.
One bad byte destroys the only copy of unsaved work, silently.
**Fix:** rename to `autosave.corrupt-<ts>.json`, surface a `toast.error` with keep/report actions, delete only on explicit confirmation.

### C7 · The shortcuts dialog documents a key that does something else
`use-keyboard-shortcuts.ts:321-323` binds `mod+0 → fitZoomStore()`; `:339-341` binds `mod+1 → resetZoomStore()`. Meanwhile `dialogs/keyboard-shortcuts-dialog.tsx:92` documents **`Ctrl+0` as "إعادة الضبط (100%)"**. True 100% is `Ctrl+1`; `Ctrl+0` actually means fit-all. `Ctrl+Shift+0` (fit-width) and `Ctrl+Alt+0` (auto-fit) are registered at `:327`/`:333` but documented nowhere.
**Fix:** correct the row to `Ctrl+1` and read the whole table from `WORKSPACE_STATE_COMMANDS` so the dialog cannot drift again.

## 2. High — real functional or invariant breakage

### H1 · Editing an image's shadow does nothing while a filter is active
`konva/elements/image-node.tsx:258-261` puts `shadowColor/shadowBlur/shadowOffsetX/shadowOffsetY` on the **cached** `KonvaImage`, but the cache key at `:89` is `${filter}_${brightness}_${contrast}_${saturation}_${blur}`. `hooks/use-filter-cache.ts:62-78` re-caches only on `hasFilters`/`filterKey`/`image`/`recache`/`nodeRef` — none include shadows.
Konva's `Shape.drawScene` blits the cached bitmap, so the properties panel edits a value that never reaches the screen or the print export. Silent WYSIWYG break.
**Fix:** append the four shadow fields to `filterKey` (same node, same bitmap).

### H2 · Collage corner-radius change does not re-rasterize
`konva/elements/collage-image.tsx:115` — `filterKey = ${filter}_${brightness}_${contrast}_${saturation}`, while `cornerRadius` is applied to the cached node at `:308`. Changing the radius leaves every filtered slot rasterizing the old bitmap until a zoom/resize forces a recache.

### H3 · AI operations silently revert concurrent edits (stale capture)
`hooks/use-bg-removal.ts:284-289` and `hooks/use-ai-enhance.ts:250-261` build the patch from the element captured at job start and write it back seconds/minutes later with no freshness guard. A concurrent image swap / undo / restore is overwritten, including `originalImageSrc`.
**Fix:** re-read `useEditorStore.getState().elements.find(e => e.id === id)` at apply time, bail if `imageSrc` drifted, derive the patch from the live record.

### H4 · DPI change rewrites slot geometry outside the history system
`store/slices/print-slice.ts:31-68` remaps `slots` when `patch.dpi` changes but never calls `pushHistory`, and `HistoryEntry` (`store/types.ts:159-183`) / `captureSnapshot` (`store/slices/history-slice.ts:72-95`) omit `printSettings` entirely.
Result: Ctrl+Z reverts slot rects while keeping the new DPI — permanently desynchronized and un-undoable.

### H5 · Autosave is not flushed before the window teardown
`hooks/use-autosave.ts:193-214` performs the final write as a **floating, unawaited `saveDraft()`** inside React cleanup, while `hooks/use-window-controls.ts` drives `Quit()` immediately after. Nothing registers `beforeunload` / `OnBeforeClose`.
Any edit made in the <2 s before closing the window is silently lost.
**Fix:** expose `flushAutoSave()` and await it from a shutdown handler.

### H6 · Autosave failures below the "obvious" threshold are invisible
`hooks/use-autosave.ts:91-95` — a `SaveAutoSave` rejection is only `console.error`'d: no toast, no retry, no backoff. When the payload exceeds the Go size cap or the disk fills, persistence stops dead while the user still believes autosave is running.

### H7 · Async collage fills push history against the wrong snapshot
`store/slices/collage-slice.ts:317-330` and `:365-392` `await` an aspect measurement, then `updateSlot` + `pushHistory()` — the late snapshot reflects **current** live state, not the state at batch time. Intermediate state becomes unreachable; Ctrl+Z jumps over or merges unrelated edits.
Same class at `:443-483` and `:640-658`: `fillEmptySlots`/`fillRowSlots`/`fillColumnSlots` do not reset `zoom`/`dragX`/`dragY`/`rotation` the way `fillAllSlots` (`:419-441`) does, so a new image inherits the previous crop — and that wrong crop *is* pushed to history as if correct.

### H8 · `loadProject` does not enforce id uniqueness
`store/slices/core-slice.ts:386-394` validates numeric geometry only. A project file with duplicate ids makes every id-keyed write (`element-slice.ts:498`, `:536`, `:731`) act on **both** records — edits, deletes and z-order all fire twice.
**Fix:** `Set`-based uniqueness + `CanvasElementSchema.safeParse` inside `loadProject`, not only at the caller.

### H9 · Direct `console.*` in sensitive paths (11 sites)
`hooks/use-autosave.ts:60,69,94` · `hooks/use-keyboard-shortcuts.ts:526` · `hooks/use-async-image.ts:113` · `hooks/use-bg-removal.ts:309` · `hooks/use-face-frame.ts:266` · `hooks/use-filter-cache.ts:57` · `components/crash-recovery-dialog.tsx:55` — all in export / file-processing / project-dialog paths where the invariants mandate `createLogger('Name')`. The correct pattern already exists in the repo (`hooks/use-ai-enhance.ts:291`, `toolbar/toolbar-file-ops.tsx:33`). `lib/logger.ts:46` is the sole legitimate site.

### H10 · Real backend error text is discarded
`dialogs/refine-bg-dialog.tsx:509` `toast.error("فشل حفظ التعديلات")` · `dialogs/export-dialog.tsx:206-207` · `dialogs/print-dialog.tsx:156` · `stickers/StickerStudioDialog.tsx:341,382,514,544,565` — the Wails string is dropped. Worse, `freeform-collage/FreeformCollageModal.tsx:566` and `:638` use `String(err)`, which renders `"[object Object]"` because Wails rejects with plain strings/objects. `toErrorMessage` already exists (`dialogs/projects-dialog.tsx:2`, `dialogs/account/license-tab-content.tsx:9`) and is simply not called.

### H11 · Radix `Tabs` driven by a `role="tab"` segmented control
`dialogs/projects-dialog.tsx:357` and `dialogs/account-license-modal.tsx:206` place `<FluentSegmentedControl>` (which emits `role="tab"`) inside Radix `<Tabs>`/`<TabsContent>`. Its buttons carry `aria-selected` but no `aria-controls`, and `TabsContent`'s `aria-labelledby` points at a non-existent trigger id — the panel relationship is announced as broken.
The same anti-pattern is hand-rolled at `App.tsx:274-306` for the mode switcher with no roving `tabIndex` and no arrow keys, while `ui/blocks/fluent-segmented-control.tsx` already implements all of it.

### H12 · Window caption buttons have no keyboard focus ring
`system/window-controls.tsx:59`, `:89`, `:135` all use `focus:outline-none` with **no** `focus-visible:ring-2 …`, so Minimize/Maximize/Close are invisible to keyboard navigation. `:135` additionally hardcodes `hover:bg-[#c42b1c]`.
Root cause: `index.css:467-476` uses a **global `outline`** focus system (`*:focus-visible { outline: 2px solid var(--primary) }`) while every component uses Tailwind `ring-*` — two competing systems, so anything with `focus:outline-none` loses focus indication entirely.

### H13 · Panels animate at 200 ms
`workspace/workspace-layout.tsx:75` and `:122` combine `.fluent-panel-motion` (100 ms) with Tailwind `transition-all duration-200` on the same node. Two competing declarations, and 200 ms exceeds the project's own 150 ms ceiling for a 296 px drawer (the toolbar already uses `duration-150`).

### H14 · Escape cannot close the freeform collage modal — it only clears selection
`freeform-collage/FreeformCollageModal.tsx:455-490` registers a **capture-phase** `window` keydown that calls `stopImmediatePropagation()` for `escape`, then its own branch does `setMultiSelectedIds([])`. Radix's document-level `DismissableLayer` never sees the event, so Escape — the universal close affordance — only deselects.
**Fix:** drop Escape from `isHandledKey` and clear selection inside `onEscapeKeyDown` **without** `preventDefault`.

### H15 · A global keydown listener lives outside the sanctioned hook
The shortcuts dialog registers its own raw `window` `keydown` for `Ctrl+/` (`dialogs/keyboard-shortcuts-dialog.tsx:31-49`) in addition to the H14 listener. Grep-verified: aside from `hooks/use-keyboard-shortcuts.ts:543`, these are the only raw `keydown` registrations in `src` — two owners for global keys is exactly what the "Single Shortcut & Palette Invariant" forbids.

### H16 · Text sizes override the scale without paired line-heights
`index.css:103-111` overrides `--text-xs: 11.5px` etc. without a matching `--text-*--line-height`. Tailwind's Latin ratio (1.33) then governs Arabic glyphs, which need more; components compensate ad-hoc with `leading-tight` (`ui/blocks/fluent-setting-row.tsx:96`) producing a ~12.5 px line box at 10 px — cramped, with clipped descenders.

### H17 · Dialog footers are forced to the physical right edge in RTL
`ui/dialog.tsx:96` and `ui/alert-dialog.tsx:62` use `text-center sm:text-right`. Every dialog that *does* set `dir="rtl"` (crop, keyboard-shortcuts, projects, export, print, refine-bg, batch-insert — nearly all of them) gets its header pushed to the right edge regardless of direction.

## 5. Verified OK — do not re-open these

- **Build baseline is clean** — `tsc --noEmit` 0 errors, `eslint src` 0 problems. Nothing below is a compile issue.
- **History isolation** — `captureSnapshot`/`restoreEntry` use `array.map(el => ({...el}))` (`history-slice.ts:74-75,100-101`); snapshots share no identity with live state and base64 payloads are shared by reference, never duplicated. Count cap + byte cap + eviction, `historyIndex` recompute, redo-branch truncation, and selection clearing on undo/redo are all correct.
- **No whole-store Zustand subscriptions** anywhere in `src`; no object-returning selector without `useShallow`; no `JSON.parse(JSON.stringify())` / `structuredClone` in `frontend/src`.
- **No in-place mutation** of `state.elements`/`state.slots` outside local copies.
- **Schema gate on load** — `deserializeProjectFile` runs `ProjectFileSchema.safeParse` with explicit version rejection, and zod strips unknown keys, so arbitrary project keys cannot reach Konva props.
- **Slot rebalancing** on mode entry, canvas resize, and gap/margin/DPI change is implemented with nearest-center re-matching that preserves images and ids.
- **License path error handling** funnels through `toErrorMessage` with epoch + single-flight race guards (`license-slice.ts:128-136,184-222`).
