# خارطة طريق الإصلاح

المراحل متسلسلة؛ لا تبدأ مرحلة تعتمد على أمان أو جودة غير مثبتة قبل إغلاق سابقتها.

## المرحلة 0 — احتواء المخاطر الأمنية

**الهدف:** منع الوصول الإداري غير المقصود ومنع إساءة استخدام AI قبل أي إصدار.

- إيقاف نشر Admin Web أو تقييده مؤقتاً إن كان متاحاً للعامة.
- تدوير مفتاح Modal المكشوف وإلغاء fallback الافتراضي.
- إنشاء دور إداري مستقل وربط RLS وAdmin Web به.
- نقل AI إلى Edge Function محمية بـJWT وحصة ذرية في قاعدة البيانات.
- اختبار migrations وسياسات RLS على staging.
- تحديث toolchain Go إلى آخر patch أمني مدعوم وإعادة govulncheck.

**بوابة الخروج:** لا يستطيع حساب enterprise العادي إدارة مستخدم أو مفتاح، ولا يمكن استدعاء Modal من دون تفويض خادمي، ولا توجد نتيجة symbol vulnerability في toolchain الإصدار.

## المرحلة 1 — جعل خط الجودة موثوقاً

**الهدف:** منع دمج أو إصدار كود لا يمر بالفحوصات.

- إصلاح جميع أخطاء lint من جذورها.
- إصلاح mock والـadapter الخاصين بـWails في E2E.
- تشغيل Chromium E2E في CI، وإبقاء Firefox كفحص دوري إلى أن تستقر المدة.
- تثبيت أوامر موحدة: lint، typecheck، unit، e2e، Go tests، race، build، audit.
- إضافة thresholds ابتدائية للتغطية ومنع هبوطها.

**بوابة الخروج:** كل أوامر الجودة خضراء على CI، ولا توجد اختبارات مكسورة أو skipped بلا تذكرة.

## المرحلة 2 — سلامة البيانات والطباعة

**الهدف:** لا فقد للخصائص، وما يراه المستخدم يطابق ما يطبعه.

- توسيع ProjectSchema لكل الحقول الفعلية، بما فيها slot transforms وrepeatMode.
- إصلاح autosave ليعتمد DTO كاملاً.
- إصلاح logout الحقيقي، وتحديد سلوك الخطة المجانية.
- بناء layout مشترك للمعاينة وطلبات Go.
- معالجة border وradius وcrop وfilter وrepeat في معاينة الكولاج.
- اختبار round-trip للمشروع واختبار visual أو fixture للطباعة.

**بوابة الخروج:** مشروع مع صورة ونص وشكل وكولاج وإعدادات طباعة يعود نفسه بعد autosave وDB وJSON؛ وfixtures للطباعة تطابق المعاينة ضمن tolerance موثق.

## المرحلة 3 — الاعتمادية والأداء

**الهدف:** منع فقد الصور وتجمّد الواجهة مع الحفاظ على قواعد أداء Konva.

- إنشاء media_refs أو registry ذري للمراجع، ثم quarantine وحذف مؤجل.
- نقل إزالة الخلفية إلى Worker وتحميل المكتبات والنماذج عند الطلب.
- توحيد audit AI في خدمة خادمية بدلاً من localStorage وبيانات نموذجية.
- إزالة TooltipProvider المكرر وتقليل any في مسارات Konva والطباعة.
- تقسيم bundle وقياس حجم البداية والتفاعل قبل وبعد.

**بوابة الخروج:** لا يحذف cleanup ملفاً مرجعياً في اختبارات التكامل، ولا يحجب AI تفاعل الواجهة، ويهبط حجم initial bundle وفق ميزانية موثقة.

## المرحلة 4 — الإصدار والتشغيل

**الهدف:** إصدار قابل للتكرار والدعم.

- README تشغيلي، release checklist، وخطة rollback.
- smoke test يدوي للرفع والحفظ والاسترجاع والتصدير والطباعة والترخيص.
- لوحة إدارة تعتمد عمليات خادمية مسجلة، مع تصدير CSV آمن.
- توثيق سياسة النسخ الاحتياطي واستعادة مشاريع المستخدم.

**بوابة الخروج:** إصدار Windows مبني من CI، موقّع عند توفر الشهادة، ومرفق بنتائج الفحوصات وsmoke test.
