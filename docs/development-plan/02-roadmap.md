# خارطة الطريق

هذه الخطة مرتبة حسب تخفيض المخاطر أولًا، ثم تثبيت عقود البيانات والإخراج، ثم تحسين الأداء والتجربة.

## المرحلة 0: تثبيت خط الجودة

الهدف: الوصول إلى حالة يستطيع الفريق الوثوق بها قبل أي تطوير جديد.

النطاق:

- إصلاح lint.
- إصلاح e2e أو تقليصها إلى smoke tests مستقرة.
- تحديث CI ليشغل الفحوصات الضرورية.
- معالجة ثغرات Vite/esbuild بترقية مخططة.

مخرجات القبول:

- `npm run lint` يمر.
- `npm run typecheck` يمر.
- `npm test` يمر.
- `go test` يمر بدون التقاط `frontend/node_modules`.
- `npm run test:e2e` يمر أو توجد مجموعة smoke مستقرة مفعلة في CI.
- `npm audit --audit-level=moderate` لا يفشل أو توجد exception موثقة ومؤقتة.

## المرحلة 1: عقد بيانات موحد للمشروع

الهدف: منع فقدان البيانات بين autosave، JSON، DB، والاستيراد.

النطاق:

- بناء serializer مركزي.
- توسيع Zod schemas لتغطي كل الحقول.
- إضافة `version` وmigrations.
- توحيد مسارات save/load/export/import.
- إضافة اختبارات عقد.

مخرجات القبول:

- حفظ مشروع يحتوي صورًا، نصوصًا، أشكالًا، ظلالًا، إعدادات كولاج، وإعدادات شبكة ثم تحميله يعيد نفس الحالة.
- autosave يستخدم نفس serializer.
- backup/import يستخدم validation وليس JSON parse فقط.

## المرحلة 2: إخراج وطباعة مطابقان للكانفس

الهدف: ما يراه المستخدم هو ما يتم تصديره وطباعته.

النطاق:

- توحيد renderer أو جعل backend يطبع snapshot كامل من Konva.
- إضافة validation لطلبات الطباعة.
- ضمان دعم النصوص والأشكال والفلاتر والشفافية.
- إضافة اختبارات pixel/visual.

مخرجات القبول:

- ملف الطباعة يحتوي جميع العناصر المرئية في الكانفس.
- لا يمكن توليد canvas يتجاوز حدود الذاكرة المحددة.
- export PNG/JPG والطباعة يستخدمان نفس دلالات الألوان والفلاتر.

## المرحلة 3: إزالة الخلفية والذكاء الاصطناعي

الهدف: جعل الميزة قابلة للتوقع، قابلة للفشل اللطيف، وقابلة للاختبار.

النطاق:

- تحديد سياسة online/offline.
- تحديث script تنزيل النماذج أو حذف ادعاء النماذج المحلية.
- إضافة progress/cancel/retry واضح.
- قيود حجم قبل تشغيل inference.
- tests للworker messages.

مخرجات القبول:

- أول استخدام يشرح متطلبات التنزيل أو يعمل offline من assets.
- فشل الشبكة يعطي رسالة قابلة للتصرف.
- لا يبدأ inference على صورة بحجم خطر.

## المرحلة 4: الأداء وتجربة التحرير

الهدف: تقليل زمن startup وتحسين سلاسة التحرير.

النطاق:

- code splitting للحزم الثقيلة.
- lazy-loading للحوارات والAI.
- ضبط Konva caching وتنظيف الذاكرة.
- إصلاح history noise في nudging والسحب.
- تحسين mobile/accessibility.

مخرجات القبول:

- انخفاض حجم initial JS.
- لا توجد re-renders مكلفة من effects مع setState متزامن.
- تحسن ملموس في فتح التطبيق وتفاعل السحب.

## المرحلة 5: المنتج والإصدار

الهدف: جعل التطبيق قابلًا للتوزيع والدعم.

النطاق:

- README حقيقي.
- Release checklist.
- smoke test يدوي.
- سياسة backup/restore.
- telemetry محلية اختيارية أو logs منظمة مع تدوير.

مخرجات القبول:

- يمكن لمطور جديد تشغيل وبناء واختبار التطبيق من README.
- يمكن إصدار build جديد بقائمة تحقق واضحة.
