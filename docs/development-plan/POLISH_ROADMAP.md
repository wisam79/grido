## مؤشر الاستئناف الحي (Live Session Pointer)

> **إلزامي لكل وكيل عند بدء أي جلسة تطويرية (ما لم يطلب المالك مهمة أخرى صراحةً):**
> اقرأ هذا الصندوق والتوجه المعتمد أولاً، وأعلن آخر إنجاز وحالة النطاق المعتمد وأي عوائق. اتّبع بروتوكول الاستئناف في `.agents/rules/architecture-governance.md`؛ لا تستأنف جولة انتهت أو فحصاً أُلغي، ولا تبدأ `PR-01` أو أي توسعة مؤجلة تلقائياً. حدّث الحالات والمؤشر وسجل الجلسات بالأدلة الفعلية في الجلسة نفسها.

| المؤشر | القيمة الحالية |
| --- | --- |
| **آخر مهمة مكتملة** | **تشخيص وإصلاح عيوب الواجهة وتصميم المحرر من لقطات المعاينة السبع** (بطلب المالك · تحقق محلي مستهدف PASS دون commit/push) |
| **المهمة الحالية / التالية** | **لا مهمة نشطة أو تالية تلقائية**؛ `AC-01` ملغاة بطلب المالك |
| **المسار النشط** | انتهاء جولة الصقل للنطاق الحالي؛ صيانة عند ظهور مشكلة فقط، دون توسعة ميزات أو إعادة هيكلة مفتوحة |
| **حالة النطاق الأصلي** | **6 مهام مكتملة (`FF-01…FF-06`)؛ 10 بنود مؤجلة (`PR` / `ST` / `CP`)**. العدد جرد للنطاق الأصلي، لا نسبة جهد ولا وعد بإكماله. |
| **حالة تجربة المستخدم** | أفاد المالك: «انا جربت بنفسي والامور تمام»؛ وتم تنفيذ جولة الهوية البصرية وجولة إصلاح عيوب لقطات الواجهة السبع بطلبه الصريح |

## قواعد الإغلاق والقبول (Definition of Done)

لا تُحوَّل أي مهمة من `⬜ pending` أو `🔄 in_progress` إلى `✅ done` إلا بعد تحقق جميع الشروط الآتية فعلياً:
1. **نظافة هندسية محدودة بالنطاق:** عند إصلاح عيب، عدّل المصدر الواحد دون إضافة ازدواجية غير مبررة أو كود ميت، واحترم ثوابت Konva والأداء وسلامة الملفات في `.agents/AGENTS.md` و`.agents/rules/`؛ لا توسّع الإصلاح إلى حملة إعادة هيكلة.
2. **التحقق المحلي المستهدف عند تعديل الكود (دون E2E أو Full Suite):** اجتياز ملفات Vitest المتأثرة منفردة ومتسلسلة (`--maxWorkers=1 --no-file-parallelism --coverage.enabled=false`)، بالإضافة إلى `npm --prefix frontend run typecheck` و`npm --prefix frontend run lint` و`npm --prefix frontend run format:check` (وما يقابلها في Go إن تأثر الباك إند). تحديث الخطة فقط يحتاج بوابة التوثيق وسلامة diff، ولا يثبت قبول التطبيق.
3. **مزامنة الوثائق:** تحديث حالة المهمة و«مؤشر الاستئناف الحي» وسطر جديد في «سجل تسليم الجلسات» أدناه + إنشاء fragment في `changelog/fragments/` + تحديث `docs/features-tracker.md` + نجاح `node scripts/docs-gate.mjs --strict-refs`.
4. **الاعتماد السحابي (عند الدفع):** إن طلب المالك الرفع أو اكتملت الجولة بالدفع، يُسجَّل `Commit SHA` ومعرّف تشغيل CI الناجح في «سجل تسليم الجلسات».

**مفاتيح الحالة:** `⬜ pending` | `🔄 in_progress` | `✅ done` | `⏸️ blocked` | `⏸️ deferred` (مؤجل بقرار نطاق، لا عطل ولا مهمة منفذة).

**إعادة فتح المؤجل:** يلزم وصف مشكلة يومية أو حاجة استخدام موثقة لا يحلها الموجود، ونطاق صغير ومعيار قبول قابل للقياس وموافقة صريحة من المالك. لا موعد ولا ترتيب تنفيذ تلقائي للبنود المؤجلة؛ صياغاتها أدناه نطاقات مقترحة محفوظة وليست معايير إغلاق للجولة الحالية. `PR-01` لا يبدأ تلقائياً، و`CP-03` لا يتحول إلى حملة إعادة هيكلة.
